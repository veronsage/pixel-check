# pixel-check
Приложение для распознавания AI-сгенерированных изображений с помощью предобученной ML-модели. Загрузка изображений, отображение результатов классификации и оценка качества распознавания на тестовом наборе.

# Разработка приложения для распознавания AI-сгенерированных изображений

## Описание задания

В рамках задания необходимо разработать приложение, которое принимает изображение от пользователя и с помощью готовой предобученной ML-модели определяет, относится ли оно к реальным или AI-сгенерированным изображениям.

Приложение должно предоставлять простой интерфейс загрузки изображения, показывать результат классификации и оценку модели для класса «AI-сгенерированное». Также необходимо протестировать приложение и проанализировать случаи ошибочного распознавания.

Ориентировочная трудоемкость — **10–12 часов**, включая тестирование, подготовку отчета и запись демонстрационного ролика. Срок выполнения — до 10 дней с момента открытия задания.

## Цель работы

Получить практический опыт интеграции предобученной ML-модели в пользовательское приложение, обработки входных файлов и оценки качества классификации.

## Ожидаемый результат

По итогам работы должны быть подготовлены:

- работающее приложение для анализа изображений;
- исходный код и инструкция по установке и запуску;
- краткий отчет о тестировании;
- демонстрационный ролик.

Обучение или дообучение модели в рамках задания не требуется.

## Необходимые знания и инструменты

Для выполнения задания потребуются базовые навыки программирования на Python, установки зависимостей и работы с Git.

Рекомендуемый стек:

Работа с моделью может потребовать подключения к интернету для первоначального скачивания ее файлов.

## Функциональные требования

### Загрузка изображения

Приложение должно позволять пользователю загрузить одно изображение в формате JPG или PNG и просмотреть его перед анализом.

Максимальный размер загружаемого файла — 10 МБ.

### Анализ изображения

Для классификации необходимо использовать указанную предобученную модель и рекомендованную для нее предобработку данных.

После анализа приложение должно показывать:

- предсказанный класс: «Реальное изображение» или «AI-сгенерированное изображение»;
- оценку модели для класса «AI-сгенерированное» в процентах.

В отчете необходимо указать правило выбора класса или используемый порог.

Оценка модели не является доказательством происхождения изображения. В интерфейсе следует разместить пояснение: «Результат может быть ошибочным и отражает оценку модели».

### Обработка ошибок

Приложение должно корректно обрабатывать:

- неподдерживаемый формат файла;
- поврежденный файл или файл, который не является изображением;
- превышение допустимого размера;
- ошибку загрузки или выполнения модели.

При ошибке пользователь должен видеть понятное сообщение. Приложение должно сохранять возможность повторной загрузки файла.

### Пользовательский интерфейс

Интерфейс должен содержать:

- название и краткое описание приложения;
- элемент загрузки файла;
- предварительный просмотр изображения;
- кнопку запуска анализа;
- результат классификации и оценку модели;
- сообщения об ошибках и пояснение об ограничениях результата.

## Порядок выполнения

### 1. Подготовить окружение

1. Создайте собственный репозиторий для решения.
2. Создайте виртуальное окружение Python.
3. Установите необходимые зависимости.
4. Зафиксируйте зависимости в файле `requirements.txt`.
5. Проверьте возможность загрузки и запуска модели.

### 2. Реализовать классификацию

1. Подключите предобученную модель.
2. Проверьте соответствие выходных меток классам.
3. Реализуйте чтение изображения и необходимую предобработку.
4. Получите предсказание и оценку для класса «AI-сгенерированное».
5. Проверьте работу на одном реальном и одном AI-сгенерированном изображении.

### 3. Разработать интерфейс

1. Добавьте загрузку и предварительный просмотр изображения.
2. Добавьте запуск анализа.
3. Выведите предсказанный класс и оценку модели.
4. Добавьте индикатор выполнения анализа.
5. Разместите пояснение об ограничениях результата.

### 4. Добавить обработку ошибок

Проверьте работу приложения с неподдерживаемым, поврежденным и слишком большим файлом. Убедитесь, что после ошибки можно загрузить другое изображение.

Проверяйте содержимое файла, а не только его расширение.

### 5. Провести тестирование

Используйте не менее **40 изображений**:

- 20 реальных;
- 20 AI-сгенерированных.

Метки должны быть известны из источника данных. Не определяйте происхождение тестового изображения только по его внешнему виду.

Для каждого изображения сохраните:

| Файл | Истинный класс | Предсказанный класс | Оценка AI-класса | Верно / неверно |
|---|---|---|---|---|
| example.jpg | Реальное | … | … | … |

Рассчитайте:

- общую долю правильных ответов — accuracy;
- количество реальных изображений, ошибочно признанных AI-сгенерированными;
- количество AI-сгенерированных изображений, ошибочно признанных реальными.

**Accuracy = количество правильных предсказаний / общее количество изображений.**

Укажите происхождение тестовых данных. Не подбирайте порог по результатам этого же набора, если затем используете его для итоговой оценки.

### 6. Проанализировать результаты

Разберите до трех ошибочных предсказаний. Если ошибок меньше — рассмотрите все найденные.

Для каждого случая укажите:

- истинный и предсказанный класс;
- оценку модели;
- возможные причины ошибки.

Предположения о причинах ошибок следует отделять от подтвержденных наблюдений. Если ошибок на выбранном наборе не оказалось, отметьте это и объясните, почему небольшой набор не позволяет сделать вывод о безошибочной работе приложения.

### 7. Подготовить материалы для сдачи

Дополните README своего решения инструкцией по установке и запуску, подготовьте отчет и запишите демонстрационный ролик.

## Критерии приемки

Задание считается выполненным, если:

- приложение запускается по инструкции из README;
- реализована загрузка и проверка изображений;

Фиксированный минимальный уровень accuracy не устанавливается. Оцениваются корректность реализации, воспроизводимость тестирования и обоснованность выводов.
